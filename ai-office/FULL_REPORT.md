Дата сверки: 2026-10-16, Europe/Moscow (UTC+3). Секреты, пароли, LAN-адреса и идентификатор владельца в этот файл не входят.

Сообщение «Тест» принято ботом и снова закончилось без текста ассистента.

Повтор этого вызова не делался. Под gateway к моменту «Тест» уже работал 89 минут и не перезапускался на этой ошибке. Под cursor-bridge работает 9 часов и за это время записал ту же `InternalServerError` дважды: на «Привет» и на «Тест».

Сейчас пустое сообщение говорит, что фото, документ и голосовое сохраняются локально, а стикеры, видео и видеосообщения нет. Карточка «Бот добавлен в сообщество AiOffice» рисуется Telegram. Бот отвечает только в личном чате.

## Что говорит эта пара ошибок

Оба живых вопроса дошли до Cursor и вернулись без текста примерно за 20 секунд. Список моделей в предыдущей проверке отвечал 200, и `grok-4.7` в нём был. Новый запрос к каталогу и новый вызов модели в этой сверке не делались.

На [status.cursor.com](https://status.cursor.com/) 15 октября 22:25 UTC начался инцидент «Elevated errors affecting Grok models»: часть запросов падала с ошибкой ёмкости. Инцидент закрыт 16 октября 05:20 UTC, страница сейчас пишет, что системы в норме. Оба наших вызова позже этого закрытия: 06:42 UTC и 08:23 UTC. Страница статуса сама по себе эти два отказа не объясняет, но симптом тот же: внутренняя ошибка, короткий обрыв, пустой результат, нет usage.

Два резерва по $0.50 держатся в окне допуска ($20 за 7 дней и $100 за месяц), в том числе для `uncertain`. В `usage_costs` оценки по этим двум задачам нет. Фактический счёт подтверждается только суммой из Cursor Dashboard. Usage API аккаунта остаётся `feature_unavailable`.

## Что сделано за весь период

Работа шла только на новой VM 115 `ai-office-k3s-01`. Гости media, proxy, ausra и wg-hub не менялись. Firewall хоста, DNS, reverse proxy и хранилище Proxmox не менялись. Новых платных аккаунтов и покупок нет.

### Площадка

- Proxmox VE 9.2.2, узел pve. VM 115: Ubuntu 24.04.5, 8 vCPU, 32 GiB, 512 GiB, k3s v1.36.5+k3s1.
- Пространства имён: `ai-core`, `ai-agents`, `ai-jobs`, `ai-data`, `ai-integrations`, `ai-observability`.
- На сверке 16 октября 11:26 MSK все пять прикладных подов Ready, рестартов 0: gateway, job-launcher, postgres-0, cursor-bridge, litellm. Те же гости running. Прежний сайт отвечает HTTPS 200, nginx/1.22.1.

### Данные

- PostgreSQL 17, PVC 10 GiB. Роль приложения без superuser, CREATEDB и CREATEROLE.
- Схема до версии 3: задачи, outbox, файлы, сверка расходов, задания специалистов, подтверждения.
- Ежедневный зашифрованный логический дамп: 01:10 UTC и jitter до 5 минут, хранение 7 дней, на диске той же VM. Дамп `aioffice-20261015T214444Z.dump.age`, SHA-256 `ef56b48f0825651e251dfed54d07de1646ab04d972a3f66d577850b942e7781d`, восстановлен в отдельном временном PostgreSQL. Ключ age лежит вне git.
- Независимая копия диска VM и проверка полного восстановления VM не делались.

### Telegram

- Бот @ink1rbuh_bot, long polling, один владелец, только личный чат.
- Команды задач, заметок, напоминаний, `/timezone`, `/pause`, `/resume`, `/stopall`, `/budget`, `/calendar`, черновик письма без отправки.
- Часовой пояс владельца в базе и в окружении gateway/launcher: `Europe/Moscow`. `/timezone +3` сохраняет ту же зону. Пустая зона больше не отключает напоминания.
- Доставка Telegram не обещает exactly-once: у sendMessage нет прикладного ключа идемпотентности. Неясный сетевой исход остаётся `uncertain`.

### Ассистент

- Обычный диалог идёт в Grok 4.7 через официальный Cursor SDK, отдельный под `cursor-bridge`. Tools, shell и MCP выключены.
- Один вызов одновременно, отмена на 60 секундах, резерв $0.50, потолки $20/7 дней и $100/месяц. Платного автоповтора нет.
- В prompt попадают последние 3 успешных диалога этого владельца. Передача текстов разрешена владельцем.
- Два ранних smoke-ответа, с хоста и из Pod, завершились текстом `ai-office-ok`. Оценки $0.010692 и $0.010686. Это не счёт Dashboard.
- После этого живые «Привет» и «Тест» оба получили `InternalServerError`.

### Сеть

- Обязательный прозрачный SOCKS5 TUN на всю VM, DNS через DoH в том же контуре, отдельный запрет прямого выхода с eth0.
- Проверены запрос без proxy env, отказ при остановленном TUN и рост счётчика CNI REJECT на запрещённом соединении к PostgreSQL.
- Исходящие вызовы календаря идут только через уже существующий HTTP-proxy. Правило `0.0.0.0/0` для gateway не добавлялось.

### Launcher, файлы, подтверждения

- `job-launcher` в `ai-core`. Токен Kubernetes есть только у него. Gateway токен не монтирует.
- Роль launcher создаёт Job и Secret только в `ai-jobs`. Job специалиста без shell, без токена Kubernetes и без платного повтора. Живой `/job` не запускался: он потратил бы резерв Cursor.
- Подтверждение: личный чат, кнопки «Разрешить» и «Отклонить», срок 15 минут, одноразовый hash. Разрешение потребляется до внешнего вызова.
- Файлы: allowlist MIME, не больше 2_000_000 байт, sha256, байты в `stored_files`. Голос локальный; `LOCAL_TRANSCRIBER` пустой, платного распознавания нет. MIME с параметром, например `audio/ogg;codecs=opus`, принимается.

### LiteLLM

- Образ `v1.83.14-stable.patch.3`, пустой `model_list`, без ключей провайдеров.
- В образе нет Prisma query engine, поэтому `DATABASE_URL` снят и `store_model_in_db: false`. Память: request 1 GiB, limit 2 GiB.
- `/health/liveliness`, `/health/readiness` и `/v1/models` отвечают 200. `/global/spend` отвечает 500 `No db connected`. В `/budget` это «недоступен», а не ноль и не счёт Cursor.

### Календари

- Оба провайдера выбраны: Google и Яндекс. Черновик: `/calendar create google 2030-01-01T12:00 текст` или `yandex`.
- Событие на один час, без участников, наружу только после кнопки и только один раз. Пробное событие не создавалось.
- Яндекс CalDAV: секрет в кластере, не в git. Чтение `PROPFIND` вернуло 207.
- Google выбран в коде. Токена Calendar API нет, поэтому кнопка «Разрешить» для Google остаётся локальной и наружу не ходит. Пароль IMAP к Calendar API не подходит.
- Почта наружу не отправляется: writer не подключён.
