# Решения, 2026-10-16

- ADR-001: продолжать только в существующей VM 115; прежние проекты не менять. Новый PVE storage не создавать.
- ADR-002: обязательный transparent SOCKS5 TUN + отдельный egress guard вместо зависимости только от proxy env. Даже приложение без поддержки HTTP proxy остаётся на обязательном proxy-маршруте. DNS через proxied DoH.
- ADR-003: первая версия — модульное Python-приложение с FastAPI/SQLAlchemy/PostgreSQL; разделение процессов вводится там, где нужна изоляция ключей. Очередь и outbox — PostgreSQL, Redis пока не нужен.
- ADR-004: по выбору владельца Grok 4.7 доступен через Cursor API key. Официальный Cursor SDK предоставляет агентный runtime, не raw inference API; используем отдельный адаптер с tools=[] и пустым workspace. Его нельзя называть развёрнутым LiteLLM или полным G3. [Контракт SDK](https://cursor.com/docs/sdk/python).
- ADR-005: модель только пишет текст. Все продуктовые записи выполняются доверенным кодом команд. Календарь/почта/платежи не подключены, внешних writer-capabilities нет.
- ADR-006: модель получает последние 3 завершённых диалога только своего владельца. Передача текстов в Cursor/Grok явно подтверждена владельцем.
- ADR-007: один LLM-вызов одновременно, таймаут 60 секунд, лимит текстового вывода, без платных автоповторов. $0.50 резерв на запрос, $20/7 дней и $100/месяц для допуска. get_usage недоступен; оценки и резервы не выдаются за фактическое списание. [Особенности usage API](https://cursor.com/docs/sdk/python).
- ADR-008: Telegram sendMessage не имеет прикладного idempotency key. Сетевой неопределённый исход → uncertain и проверка оператором. Не обещать exactly-once доставку. [Telegram API](https://core.telegram.org/bots/api).
- ADR-009: локальный encrypted logical backup плюс ручная копия на компьютер — первый проверенный restore, но не завершённая схема постоянного независимого backup и не VM backup.
- ADR-010: smoke Job проверяет capability и долговечность артефакта. Полноценного исследователя и job-launcher этот тест не заменяет.
- ADR-011: фактическое списание подтверждается только суммой, перенесённой из Cursor Dashboard (`dashboard_confirmed`). Оценка токенов, резерв $0.50 и ответ LiteLLM остаются недоказанным ledger. Usage API аккаунта — `feature_unavailable`.
- ADR-012: LiteLLM запущен как пустой proxy без ключей провайдеров и без `DATABASE_URL`. Образ не содержит Prisma query engine; подключать базу в этом образе нельзя. Spend остаётся недоступным, а не нулём.
- ADR-013: Kubernetes token есть только у `job-launcher`. Gateway его не монтирует. Job специалиста не имеет shell, токена и платного повтора. Подтверждение одноразовое. Голос хранится локально и не уходит в платный STT.
- ADR-014: часовой пояс владельца — Europe/Moscow (UTC+3). `+3` и пустое значение означают эту зону.
- ADR-015: календари Google и Яндекс. Событие без участников, один час, только после кнопки. Яндекс ходит в CalDAV через уже существующий HTTP-proxy. Google ждёт OAuth refresh token. Почта наружу не отправляется. Секреты календаря в git не входят.
