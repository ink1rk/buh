## Что исправлено

R6-P0-01. `safe_get` проверяет каждый Location до следующего запроса. Другой scheme, host или port даёт `redirect_cross_origin`, второй запрос не делается, `Authorization` остаётся на исходном origin. Тот же origin можно пройти, но `If-None-Match` и `If-Modified-Since` снимаются. `http`, приватный адрес, цикл и четвёртый редирект блокируются. Причина отказа не содержит токен.

R6-P1-02. ETag хранится в `source_endpoint_states` по паре источник+URL. Миграция `0002_endpoint_state`. 304 относится только к своему URL. Источник получает `not_modified`, только если все ответы 304 и новых элементов нет. Смесь 200 и 304 остаётся успешной, если обход полный. 5xx, 429 или обрыв бюджета при уже разобранных элементах дают `partial`, а не `ok`.

R6-P1-03. Бюджет Hacker News считается внутри источника. `report.requests` остаётся общей метрикой и больше не обнуляет загрузку элементов. Квоты коллекций делятся, повторяющиеся ID не запрашиваются второй раз. Нехватка бюджета даёт `partial`.

R6-P1-04. Пары GitHub Releases не разрезаются нечётным cap. Метаданные складываются по `owner/name` из URL и используются только если `full_name` совпал. Сбой метаданных одного репозитория не переносит лицензию на другой.

R6-P1-05. `LLM_BASE_URL` — корень, `LLM_API_PATH` по умолчанию `/api/chat`. Хост должен быть в `LLM_ALLOWED_HOSTS` (по умолчанию loopback). Редирект клиента модели не следует. VM 104 не вызывалась.

R6-P1-06. `HF_READ_TOKEN` отправляется только на `huggingface.co` и `cdn-lfs.huggingface.co`. Публичный API работает и без него. Это записано в README. Токен не обязателен.

R6-P2-07. `/health/ready` возвращает `scope=database` и не говорит, что воркеры здоровы. `/health/components` доступен только OWNER и показывает heartbeat collector/scheduler, каталог карточек и Redis без URL. Аноним получает 401, редактор 403.
