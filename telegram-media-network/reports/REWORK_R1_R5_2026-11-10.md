## P0-01. HTTP-транспорт сборщика

Сделано в `app/adapters/live_http.py`, `app/pipeline/urlsec.py` (`resolve_checked`), `app/workers/run.py` (`collect_cycle`), `app/workers/collect.py`.

- `PinnedHTTPTransport` делает один DNS-разбор через `resolve_checked`, затем `socket.create_connection` на этот IP. TLS проверяется `ssl.create_default_context`, имя сервера остаётся hostname. Редиректы клиент сам не следует. Тело ограничено `MAX_BYTES`. Несовпадение `Content-Length` даёт `truncated`. Таймаут, TLS и сеть становятся `TransportError`, а не `ok`.
- `collect_cycle` при `SOURCE_MODE!=live` выбрасывает даже переданный транспорт. При `live` без подмены создаёт `PinnedHTTPTransport`. Поставляемый Compose оставляет `SOURCE_MODE=offline`, поэтому штатный процесс сокет не открывает.
- `collect_once(..., transport=None)` при live пишет health `error` и `live mode has no HTTP transport`.
- 401 и 403 без `Retry-After` дают `auth_error`. 429 и 403 с `Retry-After` дают `rate_limited`. 5xx и обрыв после уже разобранных элементов дают `partial`, а не стирают их. Больше 25 элементов обрезается, health остаётся `partial`. Причина пишется в `last_error` отдельно от health.

Приёмка T01–T03 закрыта тестами выше. Живой публичный API не вызывался. Защита от повторного DNS проверена подменой: приватный ответ резолвера даёт `forbidden_ip` и `create_connection` не вызывается (`test_transport_error_and_private_address_do_not_look_successful`).

## P0-02. Модель в штатном разборе

`ingest_source_item` вызывает `compose_draft`. `mock` и `manual` не создают сокет. `local` использует `LocalLLMClient`.

Клиент говорит с Ollama: тело `/api/chat` — `messages` с system и user, либо `/api/generate`, если URL заканчивается на этот путь. В user лежит JSON `source_data`. Старый конверт `{system, source_data}` как тело запроса больше не отправляется и как ответ не принимается. Ответ берётся из `message.content` или `response` и проверяется по `schemas/post_draft.schema.json`. Поле `publish` и `requires_review=false` отклоняются. Черновик остаётся `requires_review=true`. Ошибка модели добавляет `llm_fallback`, пишет audit `llm_draft` (модель, миллисекунды, короткий source id, код ошибки) и не создаёт outbox.

T07 — локальный `HTTPServer`, не Ollama на VM 104. T08 — закрытый порт `127.0.0.1:9` и отдельная проверка, что mock не вызывает `urlopen`. Это MOCK ONLY / TESTED BY CURSOR, не LIVE VERIFIED.

## P1. Источники и карточки

1. GitHub Search больше не берёт только первый запрос. Курсор `query_cursor` в `policy_json` сдвигается на число выполненных поисков и ограничен `requests_per_poll_cap`. T04.
2. GitHub Releases вызывает `parse_github_release` после документа репозитория. Пустой `watched_repos` даёт `not_configured`, не `ok`. T05 и `test_empty_release_list_is_not_configured`.
3. Hugging Face запрашивает models и spaces по `types`. Модели идут как `sort=createdAt&direction=-1&limit=5`: это первая страница новых моделей, не полный обход каталога. T06.
4. Hacker News запрашивает `topstories`, `newstories` и `showstories` из конфигурации, общий бюджет запросов общий. Источник не переводится в partial из-за отсутствия реализации.
5. Пустой `watched_projects` у PyPI останавливает опрос до чтения шумной ленты. Непустой список проходит через `filter_pypi`.
6. arXiv по-прежнему помечается как препринт. Формулировка CISA описывает запись каталога и прямо говорит, что это не вывод редакции о каждом экземпляре. `StoryEvidence.verified_at` остаётся пустым, статус `extracted`.
7. Образцы карточек — каталог `reports/cards/rework/`. Удалённые OG-картинки не используются.
8. Реклама не реализовывалась. `SPONSORED_ENABLED=false`. Просмотры и доход не выдумываются.
9. Перенос из `buh` не делался. `REPO_SPLIT.md` остаётся планом.
