# 08. Аналитика и бизнес-модель — без искусственных обещаний

## 8.1 Как монетизировать при разрешённости размещения

**Ниши:** широкая аудитория AI/news и future (спрос на охваты), B2B IT/security/infra (узкий, потенциально ценный контакт), GitHub/dev (сервисы разработчиков), HomeLab (железо/хостинг/self-hosted). Это гипотезы, не финансовый прогноз.

Потоки выручки **только после legal review**: прямые спонсорские посты, нативные интеграции с явной пометкой, разрешённые партнёрские ссылки, услуги/курсы/собственные продукты. Запрещены накрутки, подписные боты в ЛС, несанкционированные массовые приглашения, скрытая реклама и обещания гарантированного дохода.

## 8.2 Измеряемые KPI

- `approved_posts / ingested_items`, `published / approved`, `duplicate_rate`, `factual_reject_rate`, `time_to_publish`, `per_channel_daily_posts`, `source_health`;
- `subscribers_snapshot` через доступный Bot API `getChatMemberCount` с учётом прав и наличия канала (это количество участников, не точный охват поста);
- `post_views`, `reactions`, `forward_count` — **не гарантируются Bot API**. MVP: ручной ввод/загрузка в admin UI с указанием `measurement_source=manual`; автоматизированная выгрузка через MTProto/userbot не входит в MVP;
- `clicks` только если собственный HTTPS redirect/analytics endpoint отдельно утверждён по безопасности/политике privacy; до этого не выдавать UTM-переходы за измеренные клики;
- `revenue_actual`, `advertising_cost`, `source_cost`, `compute_cost`, `moderation_minutes`, `RPM/revenue per 1000 verified views` только если реальные просмотры доступны.

**Контроль качества:** KPI роста не может приводить к снижению фактической точности. Публикации — продукт, реклама — вторичный контур.

## 8.3 Модель учёта

`ad_campaigns`: рекламодатель, канал, согласованный период/слот, категория, статус legal review, source, UTM, цена, валюта, учётный документ/номер (без файлов платежей в обычной content-БД), planned views (не обещать), actual observed views если доступны, expense, invoice status, responsible person. Публичная подпись обязательно содержит юридически необходимую метку/идентификатор — после legal check.

Отчёты: еженедельный по каналам и единый месячный P&L с раздельными **фактами** и **оценками**. Без данных о просмотрах — нельзя рассчитывать фактический CPM.

## 8.4 Эксперимент запуска

1. Две недели без рекламы, редактор вручную подтверждает 100% публикаций.
2. Измерить качество на выборке ≥100 черновиков: фактологические ошибки, дубли, удержание тематики, отклики по ручным метрикам.
3. Через 30 дней сравнить аудитории тематик; убрать слабые направления или изменить часы/источники.
4. До первого платного размещения — отдельный legal compliance audit и план маркировки.

## 8.5 Минимальная панель

Вкладки: «Сводка сети», «Каналы», «Источники», «Очередь», «Качество», «Публикации», «Реклама (off by default)», «Ошибки», «Аудит». У каждого графика есть definition источника данных и строка `last_updated_at`; не подделывать недоступные Telegram post views.
