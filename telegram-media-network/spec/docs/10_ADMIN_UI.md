# 10. Требования к редакторской панели / UI

## Навигация

**Overview:** 8 карточек каналов (публикации сегодня, ожидают подтверждения, источник health, disabled/publish status), глобальный kill switch виден всегда (изменение только OWNER), графики по категориям.

**Inbox:** таблица кандидатов: заголовок, дата источника, первый обнаруженный, оригинал, предлагаемая рубрика, score, source, raw/near dup, статус фактов, наличие картинки, время до slot. Фильтры: канал, score, freshness, source, confidence, legal, duplicate, state. Массовые операции `reject`/`assign` только с подтверждением и аудитом; bulk publish запрещён.

**Review workspace:** слева источник с отдельными fact snippets и references, центр — черновик текста и confidence, справа — preview (изображение 16:9 + реальная Telegram подпись + inline URL). Версии draft, история редакций, отметки «неподтверждено»/«нет лицензии» и лишние утверждения красным, всё с human explanation. Кнопки `Исправить / Перегенерировать / Отклонить / Подтвердить / Запланировать`. Переименование канала/смена URL должны сбрасывать approval.

**Calendar:** недельный и дневной вид, 8 каналов по строкам, временная зона MSK явно у каждого слота, drag-drop разрешён только с revalidation/atomic scheduling, quiet-hours overlay. Нельзя втиснуть 3 поста в одинаковое время при нарушении min-gap.

**Sources:** health, success/error, rate budgets, last 304/200, ToS verified date, enable/disable, `watchlist` GitHub и PyPI, source test connection только read-only, import URL sandbox.

**Posts:** готовые/планируемые/опубликованные, Telegram message_id/link, статус reconciliation, отложенные/отклонённые, ручные исправления без скрытого переписывания публикации.

**Analytics:** факт, измерение, источник, last updated; недоступные Telegram views помечать `н/д`. Дельта subscribers где доступна, без искусственных значений.

**Commercial:** скрыта по feature flag; включается после legal audit. Списки кампаний, approvals, markings, расходы, доказательство показа.

**System:** errors, logs, audit, rollback version, health, backup reports; экспорт JSON/CSV без секретов.

## UX критерии

- Fewer than 3 clicks to reject/approve straightforward story from Inbox (при наличии права);
- Каждая кнопка с необратимым эффектом требует явного подтверждения, в DRY_RUN «Опубликовать» не посылает запрос;
- Приоритет важных предупреждений над score, нельзя скрыть hard-block через сортировку;
- Все даты показываются в MSK и UTC при раскрытии технических деталей;
- Web UI должен работать при 375px и ≥1280px, доступность клавиатуры, контраст, aria labels;
- В UI есть retry reconciliation flow, но нет кнопки «повторить наугад».
