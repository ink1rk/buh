# ITMS — система управления ИТ-инфраструктурой

Самостоятельно размещаемая (self-hosted) система для управления ИТ-инфраструктурой,
работой ИТ-отдела, проектами, сервисами и документацией.

Ключевой принцип: **всё связано со всем**. Оборудование, размещения, документы,
сотрудники и история изменений — это не отдельные разделы, а единая модель
объектов и связей. Раздельных, не связанных между собой справочников в системе нет.

Интерфейс — русский. Локализация заложена в архитектуру с первого дня: словари
лежат в `web/src/i18n`, добавление английского не требует изменений в компонентах.

## Что уже работает

### Phase 1 — ядро

| Раздел | Возможности |
| --- | --- |
| Дашборд | Счётчики по объектам, распределения по типам, статусам и критичности, лента изменений, качество данных |
| Объекты (CMDB) | Единый реестр конфигурационных единиц, фильтры, карточка объекта, статусы с проверкой переходов, теги, архивирование |
| Связи | Логические связи между объектами с проверкой циклов и группировкой по смыслу |
| Размещения | Иерархия «Организация → Площадка → Здание → Этаж → Помещение → Зона» с проверкой вложенности |
| Документация | База знаний с версиями, откатом к прежней версии, привязкой к объектам, сроками пересмотра |
| Сотрудники | Сотрудники, зоны ответственности, сводка нагрузки |
| История | Неизменяемый аудит: кто, что, когда и в рамках чего изменил |
| Импорт | CSV и XLSX: автоматическое распознавание кодировки и разделителя, сопоставление колонок, проверка, применение |
| Поиск | Полнотекстовый поиск PostgreSQL по всем сущностям, командная палитра по `Ctrl + K` |
| Файлы | Загрузка в MinIO с проверкой типа и размера, ссылки со сроком действия |

### Phase 2 — инфраструктурная модель

| Раздел | Возможности |
| --- | --- |
| Каталог моделей | Производители, модели, габариты, мощность, шаблоны портов `Gi1/0/{n}` |
| Оборудование | Инженерный профиль объекта: роль, hostname, IP/MAC управления, гарантия, мощность |
| Порты | Ручное заведение и разворот из шаблона модели, VLAN, сопряжение фронт ⇄ тыл панели |
| Кабели | Соединения с категорией, длиной, трассой, статусом и группой резервирования |
| Трассировка | Сквозной линк через патч-панели: от порта до конечного устройства |
| Адресация | VLAN, подсети с занятостью, ближайшие свободные адреса, назначение IP на порт |
| Отчёты | Свободные порты, нарушения резервирования, истекающая гарантия |

### Происхождение изменения

Любое изменение можно объяснить спустя год. Кроме обычного «кто и когда»
система хранит причину и ссылки на проект, изменение, задачу и документ:

```
Server-07
Power: 850 W
        └── изменено проектом PRJ-042
                     ├── Change #18
                     ├── задача #154
                     └── документ #27
```

Для критичных полей (статус, критичность, размещение, ответственный) происхождение
обязательно: запрос без него отклоняется с ошибкой `provenance_required`. В интерфейсе
у каждого поля карточки объекта есть кнопка «Откуда это значение» с полной цепочкой.

### Что осознанно отложено

Модель питания (`power_node`, `power_link`, `power_feed`, `power_measurement`),
редакторы стоек и сетевых схем, каталог сервисов/доменов/сертификатов, проекты
с переходом CURRENT → TARGET, задачи и управление изменениями спроектированы
в `docs/`, но кодом ещё не покрыты — это следующие этапы. Архитектурные решения
по ним уже зафиксированы, чтобы не переделывать ядро: электрика описывается
только моделью питания и никогда логической связью `ci_relation`.

## Устройство репозитория

```
itms/
├── api/          Бэкенд: FastAPI, SQLAlchemy 2, Alembic, PostgreSQL
│   ├── itms/
│   │   ├── api/          Маршруты, схемы, зависимости
│   │   ├── core/         Конфигурация, БД, контекст запроса, аудит, безопасность
│   │   ├── domain/       Бизнес-правила без обращений к БД
│   │   ├── infra/        Хранилище файлов
│   │   ├── models/       Таблицы
│   │   └── services/     Сценарии работы с данными
│   ├── alembic/          Миграции
│   └── tests/            Тесты домена и API на настоящем PostgreSQL
├── web/          Фронтенд: React 19, TypeScript, Vite, Tailwind 4
├── worker/       Фоновые задачи: ARQ (исходящие события, переиндексация, сессии)
└── deploy/       Docker Compose и пример переменных окружения
```

Правило зависимостей на бэкенде: `api → services → domain → models`.
Домен не знает о HTTP и о сессии БД, поэтому проверяется обычными тестами.

## Запуск через Docker Compose

```bash
cd itms/deploy
cp .env.example .env
# отредактируйте пароли в .env
docker compose up -d --build
```

Интерфейс откроется на `http://localhost:8080`.

Владелец системы создаётся при первом запуске. Если `OWNER_PASSWORD` в `.env`
не задан, пароль будет сгенерирован и напечатан в журнале контейнера `api`:

```bash
docker compose logs api | grep -i пароль
```

Поднимаются: PostgreSQL, Redis, MinIO (с включённым версионированием бакета),
API, фоновый обработчик и веб-интерфейс за nginx.

## Запуск для разработки

Нужны Python 3.12+, Node 20+ и PostgreSQL 16.

### Бэкенд

```bash
cd itms/api
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"

export ITMS_DATABASE_URL="postgresql+asyncpg://itms:itms@localhost:5432/itms"
.venv/bin/alembic upgrade head
.venv/bin/python -m itms.cli bootstrap        # владелец системы
.venv/bin/python -m itms.cli seed-demo        # необязательно: демонстрационные данные

.venv/bin/uvicorn itms.main:app --reload
```

Документация API — `http://localhost:8000/api/v1/docs`.

### Фронтенд

```bash
cd itms/web
npm install
npm run dev
```

Vite слушает порт 5173 и проксирует `/api` на `http://localhost:8000`.

## Проверки

```bash
cd itms/api
.venv/bin/ruff check .
.venv/bin/python -m pytest          # нужен PostgreSQL: тесты идут на настоящей БД

cd ../web
npm run lint
npm run typecheck
npm run build
```

Тесты API поднимают отдельную базу `<имя>_test`, прогоняют на ней миграции
и очищают таблицы между тестами, поэтому рабочие данные не затрагиваются.

## Настройка

Все параметры задаются переменными окружения с префиксом `ITMS_`
(см. `api/itms/core/config.py`). Наиболее важные:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `ITMS_DATABASE_URL` | Строка подключения к PostgreSQL | `postgresql+asyncpg://itms:itms@localhost:5432/itms` |
| `ITMS_REDIS_URL` | Redis для фоновых задач | `redis://localhost:6379/0` |
| `ITMS_S3_ENDPOINT` | Адрес MinIO или другого S3 | `http://localhost:9000` |
| `ITMS_SESSION_TTL_HOURS` | Срок жизни сессии | `168` |
| `ITMS_COOKIE_SECURE` | Cookie только по HTTPS | `false` |
| `ITMS_MAX_UPLOAD_MB` | Предельный размер файла | `50` |

Значения по умолчанию для расчёта электрики (напряжение, cos φ, коэффициент
длительной нагрузки, целевой запас, срок актуальности замера, допустимый
дисбаланс фаз) тоже настраиваются и уже видны в разделе «Настройки».
