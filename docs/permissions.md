# Разрешения и подтверждения

`core/permissions.py`. Правила собраны в одном месте: таблица уровней риска,
политика по уровням и точечные переопределения. Разбросанных по коду `if` нет.

## Уровни риска

| Уровень | Смысл | Примеры |
|---|---|---|
| `LOW` | обратимо, без внешних последствий | `create.task`, `create.note`, `notification.send` |
| `MEDIUM` | видно другим людям | `send.telegram.message`, `send.email`, `create.calendar.event` |
| `HIGH` | тратит деньги или ресурсы | `call.taxi`, `purchase.ozon` |
| `CRITICAL` | финансовая операция | `bank.transfer` |

Неизвестный тип действия считается `HIGH` — безопасное значение по умолчанию.

## Политика по умолчанию

| Уровень | Решение |
|---|---|
| `LOW` | `ALLOW` |
| `MEDIUM` | `REQUIRE_APPROVAL` |
| `HIGH` | `REQUIRE_APPROVAL` |
| `CRITICAL` | `REQUIRE_APPROVAL` |

## Исключения

1. **Подтверждено пользователем.** Если владелец сам нажал кнопку («Отправить
   вариант 2»), контекст содержит `user_confirmed=True` и второе подтверждение
   не запрашивается. Исключение — `CRITICAL`: такие действия подтверждаются
   всегда отдельно.
2. **Доверенные получатели.** `TRUSTED_PEERS` — список Telegram-идентификаторов,
   которым можно писать без подтверждения. По умолчанию пуст.
3. **Переопределения.** `POST /api/permissions/override` сохраняет решение для
   конкретного типа действия в таблице `settings`; оно перекрывает политику по
   уровню риска.

## Поток подтверждения

```
Action (MEDIUM) → WAITING_APPROVAL → уведомление владельцу
                                   │
            ┌──────────────────────┴──────────────────────┐
            ▼                                             ▼
    [✅ Подтвердить]                              [❌ Отменить]
            │                                             │
        APPROVED → RUNNING → SUCCESS                  CANCELLED
```

Карточка в Telegram:

```
⚠️ Требуется подтверждение

Действие: send.telegram.message
Риск: MEDIUM

{"chat_id": 1630534981, "text": "…"}

[✅ Подтвердить]  [❌ Отменить]
```

Срок действия подтверждения — `ACTION_APPROVAL_TTL` (600 секунд). По истечении
статус становится `EXPIRED`, и выполнить такое действие уже нельзя: фоновый
воркер ядра помечает просроченные заявки раз в минуту.

## Режимы ответа

`RESPONSE_MODE` (по умолчанию `SUGGEST_ONLY`):

| Режим | Поведение |
|---|---|
| `SUGGEST_ONLY` | ассистент только предлагает варианты, отправляет человек |
| `AUTO_SEND` | зарезервировано; глобально не включается |

## API

```
GET    /api/permissions               текущая политика
POST   /api/permissions/override      {"action_type": "…", "decision": "ALLOW"}
POST   /api/permissions/override      {"action_type": "…"} — снять переопределение
```
