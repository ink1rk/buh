# Обязательства и ожидание ответа

`domain/commitments.py`. Модуль отвечает на четыре вопроса: что я обещал, что
обещали мне, от кого я жду ответа и что уже просрочено.

## Модель

| Поле | Назначение |
|---|---|
| `id` | идентификатор |
| `direction` | `I_OWE` — обещал владелец; `THEY_OWE` — ждём от человека |
| `description` | суть обязательства |
| `counterparty_id` | контакт-контрагент |
| `due_at` | срок, если он был назван |
| `conversation_id`, `source_message_id` | откуда взялось |
| `status` | `OPEN`, `DONE`, `OVERDUE`, `CANCELLED` |
| `confidence` | уверенность извлечения |

## Как появляются

Фоново, из переписки, через structured output `CommitmentExtraction`.

Модель отвечает не на вопрос «чьё это обязательство», а на вопрос
`who_acts` — кто должен выполнить действие; сторона выводится из этого в
коде. Так сделано потому, что локальная модель путала говорящего с
исполнителем и просьба собеседника уходила не в ту сторону. По той же
причине роли в промте названы именами участников, а направление показано
на примерах.

| Реплика | Результат |
|---|---|
| «Пришлю тебе конфиг завтра» (владелец) | `I_OWE`, «прислать конфиг», срок — завтра 12:00 |
| «Пришли мне договор завтра» (владелец просит) | `THEY_OWE`, «прислать договор» |
| «Пришли мне договор завтра» (просит собеседник) | `I_OWE`: просьба в адрес владельца — его долг |
| «Может как-нибудь созвонимся» | ничего: уверенность ниже 0.5 |
| «Ок» | модель не вызывается вовсе |

Диалог владельца с самим ассистентом обязательств не создаёт: просьба
ассистенту — это задача, а не договорённость с человеком.

Дубли не плодятся: похожее (схожесть ≥ 0.6) обязательство того же направления
с тем же контрагентом возвращается существующим.

## Сроки

`parse_due()` понимает то, как люди пишут о времени: «сегодня», «завтра»,
«послезавтра», дни недели («в четверг» — ближайший четверг), «через 3 часа»,
«через 2 дня», «через неделю», «21.09», «к 14:00», «утром», «вечером». Если
срок не назван, поле остаётся пустым — выдумывать дедлайн хуже, чем не иметь
его.

## Ожидание ответа

`THEY_OWE` и есть состояние «жду ответа». Когда человек пишет в этом диалоге,
`close_on_reply()` закрывает ожидания от него: статус становится `DONE`,
публикуется `commitment.completed`.

## Просрочки

Фоновый воркер ядра раз в минуту вызывает `mark_overdue()`: у открытых
обязательств с истёкшим `due_at` статус меняется на `OVERDUE` и публикуется
`commitment.overdue`. Это точка подключения проактивных напоминаний в
Phase 13.

## Как спрашивать

| Вопрос | Ответ |
|---|---|
| «что я обещал?» | список `I_OWE` с контрагентами |
| «от кого я жду ответа?» | список `THEY_OWE` |
| «кому я должен ответить?» | тот же список `I_OWE` |
| `/inbox` в Telegram | обе стороны плюс последние диалоги с summary |
| `/todo` в Telegram | все открытые обязательства |

Намерения распознаются правилами (`core/intents.py`), поэтому такие вопросы
всегда попадают в CommunicationAgent, а не в общий чат с моделью.

## API

```
GET    /api/commitments?status=OPEN
PATCH  /api/commitments/{id}     {"status": "DONE"} | {"status": "CANCELLED"}
                                 {"description": "…"}
```
