# Память

`domain/memory.py`. Два принципа определяют весь модуль: догадка модели не
становится фактом, и не всякое сообщение достойно памяти.

## Типы

| Тип | Что хранит | Пример |
|---|---|---|
| `FACT` | устойчивый факт | «Кирилл больше не работает в Технопарке» |
| `PREFERENCE` | предпочтение или привычка | «Предпочитает короткие ответы» |
| `EVENT` | состоявшееся или назначенное событие | «18 сентября встречался с Иваном» |
| `RELATION` | связь между людьми | «Иван — коллега» |
| `PROCEDURE` | как обычно поступать | «Ивану отвечать коротко и неформально» |
| `EPISODE` | ссылка на эпизод переписки | см. `docs/conversations.md` |

Задачи и напоминания памятью **не являются**: «напомни завтра купить молоко»
порождает событие `task.candidate.detected`, а не запись в памяти.

## Провенанс

Каждая запись знает, откуда она:

| Источник | Потолок доверия |
|---|---|
| `USER_EXPLICIT` | 1.0 |
| `USER_MESSAGE` | 0.85 |
| `TOOL_RESULT`, `CALENDAR` | 0.8 |
| `TELEGRAM`, `EMAIL` | 0.7 |
| `LLM_INFERENCE` | 0.6 (`MEMORY_INFERENCE_CAP`) |

Вывод модели физически не может получить ту же уверенность, что прямое
утверждение владельца: `cap_confidence()` обрезает значение по источнику.
Записи с уверенностью ниже `MEMORY_MIN_CONFIDENCE` (0.45) не сохраняются.

Поля: `id`, `type`, `content`, `source`, `source_id`, `entity_id`, `scope`,
`confidence`, `importance`, `status`, `supersedes_id`, `conflict_with`,
`created_at`, `updated_at`, `expires_at`.

## Конвейер записи

```
MESSAGE
  ↓  тривиальное («привет», «ок») отбрасывается регуляркой, модель не зовётся
CANDIDATE EXTRACTION   (LLM, structured output: MemoryExtraction)
  ↓
CLASSIFICATION         (тип + about: owner | contact)
  ↓
VALIDATION             (длина, тип, потолок доверия, порог)
  ↓
CONFLICT CHECK         (противоречие с активными записями)
  ↓
DEDUPLICATION          (похожие записи усиливаются, а не дублируются)
  ↓
STORE / UPDATE / IGNORE
```

Исходы `remember()`: `created`, `reinforced`, `superseded`, `conflict`,
`low_confidence`, `rejected`.

## Дедупликация

Схожесть — Jaccard по значимым словам (`tokens()` отбрасывает стоп-слова).
При схожести выше `MEMORY_DEDUPE_THRESHOLD` (0.62) новая информация усиливает
существующую запись: уверенность растёт, важность берётся максимальная, текст
заменяется на более полный, если он пришёл не от модели.

Так «Кирилл любит кофе», «Кирилл предпочитает кофе» и «Кирилл часто пьёт кофе»
остаются одной истиной, а не тремя.

## Конфликты и вытеснение

Противоречие определяется по совпадению темы при противоположной полярности
(«работает в X» vs «больше не работает в X»).

* Новая информация не слабее старой → старая получает `SUPERSEDED`, новая
  ссылается на неё через `supersedes_id`. Ничего не исчезает бесследно.
* Новая информация слабее → она сохраняется со статусом `CONFLICT` и ссылкой
  `conflict_with`; в выдаче её вес уменьшается вдвое, и она видна в UI как
  спорная.

Статусы: `ACTIVE`, `SUPERSEDED`, `ARCHIVED`, `DELETED`, `CONFLICT`.

## Извлечение

`memory.search(query, entity_id)` — не «top-10 по эмбеддингу», а взвешенная
оценка:

```
score = 0.45 × пересечение слов
      + 0.25 × совпадение сущности (контакт)
      + 0.15 × важность
      + 0.10 × уверенность
      + 0.10 × свежесть (экспонента, полураспад ~45 дней)
```

Просроченные (`expires_at`) исключаются, спорные (`CONFLICT`) понижаются.
`ContextResolver` добавляет к найденному память самого контакта, чтобы в
промпте всегда был профиль собеседника.

## Архитектура поиска

Источник истины — обычные таблицы SQLite. Векторной базы в проекте нет и она не
добавлялась: на текущем объёме личной переписки токенная схожесть работает
предсказуемее и дешевле. Если позже понадобится семантический поиск, он
встанет вторым индексом поверх тех же таблиц, а `delete()` останется
физическим удалением, чтобы «забудь это» означало именно это.

## Удаление

`DELETE /api/memory/{id}` удаляет строку. Никаких скрытых копий и «мягких»
удалений: запись исчезает из выдачи, поиска и профиля контакта.

## API

```
GET    /api/memory?type=FACT&entity_id=…&status=ACTIVE
POST   /api/memory                {"content": "…", "type": "FACT", "source": "USER_EXPLICIT"}
POST   /api/memory/search         {"query": "…", "entity_id": "…"}
GET    /api/memory/{id}
PATCH  /api/memory/{id}           изменить содержание/важность/статус
DELETE /api/memory/{id}
```

В Telegram: `/memory` — что помню, `/memory сервер` — поиск. Рядом с каждой
записью показываются тип, источник и уверенность, поэтому всегда видно, почему
ассистент это «знает».
