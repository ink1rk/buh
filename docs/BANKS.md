# Подключение банков

Экран **«Банки»** (`/connections`) — единая точка, через которую операции из банка
попадают в штаб. Сейчас поддержан Ozon Банк; слой коннекторов устроен так, что
добавление следующего банка — это один класс, а не переделка импорта.

## Что реально доступно у Ozon Банка

Это важно понимать до настройки, потому что определяет всю схему работы.

| Способ | Статус | Кому доступен |
| --- | --- | --- |
| Импорт выписки (CSV / XLSX / PDF) | **Работает сейчас** | всем |
| Открытые API Банка России для физлиц (СТО БР ОПИ v2.0.0) | Стандарт вступает в силу **01.10.2026** | только аккредитованным СПУ |
| Ozon Банк для бизнеса через 1С:ДиректБанк | Есть, но это счёт ИП или ООО | предпринимателям |

**У Ozon Банка нет публичного API для личных счетов.** Ни OAuth-подключения «как в
Revolut», ни токена в личном кабинете — ничего этого банк не выдаёт частным
разработчикам. Автоматическая синхронизация без выписки означала бы вход в
приложение банка вашими учётными данными от вашего имени: это нарушает
пользовательское соглашение, ломается при каждом обновлении приложения и
подставляет доступ к деньгам. Поэтому такой путь здесь не реализован намеренно.

Клиент Открытых API (`app/connectors/open_banking.py`) написан по опубликованной
спецификации Банка России, покрыт тестами и ждёт своего момента: когда банк
откроет доступ, подключение переводится в режим `api` настройкой, а не
переписыванием кода.

## Как подключить Ozon Банк

1. В приложении Ozon Банк: **Профиль → Выписки и справки → выбрать счёт и период
   → Выписка по счёту**.
2. В приложении: **Банки → «+ Подключить»** на карточке Ozon Банка. Появится
   счёт «Ozon Банк» и область для загрузки.
3. Перетащите файл выписки в эту область (или «Выбрать файл»).

Результат импорта виден сразу: сколько операций загружено, сколько уже было,
сколько отложено, за какой период и какой остаток по счёту сообщил банк.

### Какие форматы лучше

- **XLSX и CSV** — разбираются точнее всего: есть категории, MCC-коды, статусы.
- **PDF** — разбирается эвристически, построчно. Работает, но если в выписке есть
  и CSV, берите CSV. Скан без текстового слоя распознать нельзя — об этом будет
  явная ошибка. Строки итогов и остатков пропускаются: они тоже начинаются с
  даты, но операциями не являются. Сумму без знака парсер определяет по
  формулировке («зачисление» — приход, «оплата» — расход), а выписку, где
  направление не прочесть совсем, отклоняет: испорченная история хуже отказа.

Размер файла ограничен 15 МБ, число строк в таблице — 100 000. Размер сам по
себе ничего не говорит о таблице внутри: XLSX — это архив, и пятимегабайтный
файл разворачивается в гигабайты.

Парсер не привязан к одному набору колонок: он оценивает заголовки по таблице
шаблонов. Поэтому переживает CP1251, UTF-8, UTF-16, разделители `;` и `,`,
шапку с реквизитами перед таблицей, юникодный минус, неразрывные пробелы,
раздельные колонки «Приход»/«Расход» и суммы без знака рядом с «Тип операции».

## Что происходит при импорте

1. **Дедупликация.** У каждой операции есть отпечаток: идентификатор банка, а если
   его нет — хеш от даты, суммы, валюты и описания с индексом повторения.
   Повторная загрузка пересекающегося периода не создаёт дублей, но две
   настоящие одинаковые покупки в один день сохранятся обе. Отпечаток считается
   в рамках подключения: одна и та же покупка бывает на двух картах одного
   банка, и история второй карты не должна уходить в дубли первой.
2. **Категоризация.** Сначала смысл операции (кэшбэк, проценты, перевод, снятие
   наличных), затем MCC-код, затем категория банка, затем мерчант. Формулировка
   важнее MCC: выплата кэшбэка может нести MCC того магазина, где он начислен.
3. **Баллы Ozon отбрасываются.** Часть кэшбэка Ozon платит баллами. Это не рубли,
   и в бюджет они не попадают — иначе капитал незаметно раздувается. Решает
   валюта операции: так их помечает сам банк. По описанию — никогда, потому что
   рублёвая покупка «оплачено 500 баллами и 1200 ₽» это настоящие 1200 рублей.
4. **Баланс.** Если банк указал остаток на конец периода, берётся он — остаток
   самой поздней операции, а не последней строки файла: Ozon выгружает свежее
   сверху. Выписка, которая заканчивается раньше уже загруженных операций,
   остаток не меняет и говорит об этом в предупреждениях. Если остатка в выписке
   нет, баланс счёта меняется на сумму новых операций.
5. **Непроведённые операции откладываются.** Операции «в обработке» ещё изменятся,
   поэтому они не пишутся в историю и попадут при следующей выписке.

Операции помечаются `source=import` и тегом `bank,ozon`, так что импорт всегда
отличим от ручного ввода. Отключение банка удаляет подключение, но **не** удаляет
загруженные операции — это уже ваша история.

Копия загруженного файла кладётся в `database/statements`. Вёрстка PDF у
каждого банка своя, и когда разбор её не понял, чинить его не на чем: операции
в базу не попали, а файл жил только в памяти запроса.

## Почему PDF — худший из вариантов

CSV и XLSX несут таблицу: колонки подписаны, знак суммы отделён от текста. В
PDF ничего этого нет — есть строки, и колонки в них приходится угадывать.
Поэтому разбор PDF устроен осторожно:

* **Знак валюты необязателен.** Банк печатает «₽» один раз, в шапке колонки.
  Пока знак требовался в каждой строке, до импорта доходили считанные операции,
  а остальные отбрасывались молча.
* **Границей числа служат разряды.** Без «₽» пробел внутри числа ничем не
  отличается от пробела между числами, и «-1 234,56 48 765,44» читается одной
  суммой в пять миллионов. Поэтому разряды описаны как группы ровно по три цифры.
* **Направление читается по файлу целиком.** Если минусы в выписке где-то есть,
  банк помечает ими списания — значит строка без знака это приход. Если знаков
  нет нигде, решает формулировка («зачисление», «оплата»). Если молчит и она,
  выписка отклоняется: записать приход расходом — ошибиться на две суммы.
* **Итоги и остатки пропускаются.** Они тоже начинаются с даты, и принятые за
  операции удваивали бы траты.
* **Непонятая вёрстка — отказ, а не догадка.** Если строк с датами много, а
  операций распозналось мало, разбор отказывается работать. Полгода трат не
  должны незаметно превращаться в пару строк, похожих на настоящие.

Если ваш банк умеет выгружать CSV или XLSX — берите их.

## Автоматическая синхронизация

Планировщика нет: без API банка синхронизировать нечего. Загрузка выписки —
осознанное действие раз в месяц. Когда появится доступ к Открытому API, у
подключения в режиме `api` заработает кнопка «Синхронизировать» и эндпоинт
`POST /connections/{id}/sync`.

Выписку можно загружать и не открывая браузер — через MCP-инструмент
`import_bank_statement`, см. [MCP.md](MCP.md).

## API

| Метод | Назначение |
| --- | --- |
| `GET /api/v1/connections/providers` | поддерживаемые банки и инструкции |
| `GET /api/v1/connections` | список подключений |
| `POST /api/v1/connections` | создать подключение |
| `PATCH /api/v1/connections/{id}` | переименовать, сменить счёт или режим |
| `DELETE /api/v1/connections/{id}` | отключить банк |
| `POST /api/v1/connections/{id}/statement` | загрузить выписку (multipart) |
| `POST /api/v1/connections/{id}/sync` | синхронизация через Открытое API |
| `GET /api/v1/connections/{id}/imports` | история импортов |

Операции, пришедшие из выписки, можно поправить руками на странице
«Операции» — банк иногда называет магазин так, что узнать его нельзя.
Удаление строки развязывает её с операцией банка, поэтому следующая загрузка
той же выписки вернёт её обратно, а не сочтёт дублем.

Токены доступа для режима `api` хранятся зашифрованными (`ENCRYPTION_KEY`) и
никогда не возвращаются из API — только флаг `has_credentials`. Без
`ENCRYPTION_KEY` подключение с токеном не сохраняется вовсе: запись доступа к
банку открытым текстом хуже отказа.

Адрес Открытого API проверяется при сохранении: он обязан быть `http(s)` и
вести на публичный адрес. Внутренние адреса (`127.0.0.1`, `10.*`,
`169.254.169.254`) отклоняются — клиент возвращает в тексте ошибки тело того,
до кого дотянулся, то есть без проверки это поле было бы окном на всё, что
слушает на машине. По той же причине `Links.next` обязан указывать на тот же
адрес: с каждым запросом уходит токен доступа.

## Добавить свой банк

1. Наследуйте `BankConnector` в `backend/app/connectors/`.
2. Реализуйте `parse_statement`; для табличных выписок достаточно вызвать
   `rows_to_statement(read_csv_rows(data))` — при необходимости дополните
   `FIELD_PATTERNS` в `tabular.py` названиями колонок вашего банка.
3. Зарегистрируйте класс в `_CONNECTORS` в `app/connectors/__init__.py`.

Дедупликация, категоризация, запись операций и сверка баланса уже общие — их
трогать не нужно.
