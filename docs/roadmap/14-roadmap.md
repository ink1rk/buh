# 14 — Roadmap реализации

Порядок фаз соответствует постановке (§31). Оценки даны в относительном объёме работ (S / M / L / XL), а не в календарных сроках. После каждой фазы система остаётся запускаемой и полезной.

Общее правило: **модель данных опережает интерфейс**. Экран не начинается, пока не готовы сущности, API и доменные правила, которые он показывает.

---

## Phase 0 — Архитектура (текущая фаза)

**Объём:** M
**Результат:** пакет документов `/docs` (этот набор), согласованная модель, утверждённый стек.

Готово:
- системная архитектура, слои, модули, сквозные механизмы;
- доменная модель, типы CI, таксономия связей, жизненные циклы, аудит;
- карта сущностей и связей;
- схема БД с ключами, индексами и ограничениями;
- инфраструктурная модель (сеть, интерфейсы, кабели, адресация, физика);
- Diagram Engine, Rack Editor, Power Model с методикой расчёта;
- проектное управление с переходом CURRENT → TARGET;
- документация, эксплуатация, отчётность, API, UI, roadmap.

**Критерий выхода:** владелец согласовал модель и стек; открытые вопросы (§ «Вопросы к согласованию») закрыты.

**Риски:** переусложнение базового CI. Митигация — начать с минимального набора полей, расширять по фазам.

**Риски:** трассировка через пассивку и ограничения на порты — самая тонкая часть. Митигация — покрыть unit-тестами домена до реализации UI.

## Phase 3 — Diagram Engine

**Объём:** L
**Зависимости:** Phase 2 (нечего рисовать без сети).

Состав: canvas kernel (viewport, выделение, snapping, undo/redo, экспорт SVG); типы схем NETWORK / LOGICAL / POWER (питание — после Phase 4) ; узлы-устройства с портами; рёбра, отражающие свойства кабеля; создание кабеля из схемы; группы и аннотации; автонаполнение по области/связям/сервису; автораскладки; экспорт SVG/PNG/PDF/JSON; открытие карточки объекта из схемы.

**Критерий выхода:** схема серверной строится автоматически по помещению, редактируется, сохраняется, экспортируется; изменение свойств кабеля отражается на схеме без перерисовки.

**Риски:** производительность на больших схемах. Митигация — уровни детализации по зуму и виртуализация с самого начала.

## Phase 5 — Projects

**Объём:** L
**Зависимости:** Phase 1 (задачи), Phase 4 (энергетические сценарии для полноценного CURRENT → TARGET).

Состав: проекты, этапы, вехи, участники, бюджет план/факт; универсальные задачи всех типов, зависимости FS/SS/FF/SF, подзадачи, учёт времени, повторяющиеся работы; Kanban; список с фильтрами и массовыми операциями; календарь; Gantt с критическим путём и baseline; загрузка сотрудников; `state_snapshot`, `planned_change`, `change_item`, gap analysis, применение к модели, план отката; шаблоны проектов; здоровье проекта по правилам.

**Критерий выхода:** сквозной сценарий из §21 постановки проходится целиком — от фиксации текущего состояния до обновления модели после реализации.

**Риски:** применение целевого состояния — операция с побочными эффектами на всю модель. Митигация — транзакционность, предварительная проверка конфликтов, идемпотентность, генерируемый план отката.

## Phase 6 — IT Operations

**Объём:** M
**Зависимости:** Phase 2 (объекты), Phase 5 (задачи).

Состав: изменения с полным жизненным циклом, согласованиями (включая внешние стороны), окнами работ, планом и rollback; связь правок модели с изменением в аудите; инциденты с SLA-таймерами; проблемы; плановые и регламентные работы; календарь эксплуатации; уведомления; дашборд руководителя во всей полноте; контроль работы отдела (загрузка, просрочки, выполненные работы).

**Критерий выхода:** любое изменение инфраструктуры проходит через `change` и оставляет след в истории затронутых объектов; дашборд отвечает на вопрос «что сейчас важно» без перехода по разделам.

**Объём:** M
**Зависимости:** все предыдущие (отчёты строятся по готовым датасетам).

Состав: каталог датасетов, конструктор отчётов (поля, фильтры, группировки, агрегаты, диаграммы), сохранённые отчёты и фильтры, системные отчёты из §22, экспорт CSV/XLSX/PDF, фоновая генерация больших отчётов, расписания, составной пакет документов для согласования, аналитические экраны (загрузка, портфель, ёмкость, энергетика, надёжность, качество CMDB).

## Сквозные требования по фазам

| Требование | Как обеспечивается на каждой фазе |
|---|---|
| Миграции | Каждая фаза добавляет ревизии Alembic; прогон up/down в CI |
| Тесты | Unit для доменных правил, API-тесты на PostgreSQL, e2e на ключевые сценарии фазы |
| Аудит | Новые сущности сразу включаются в механизм истории |
| Поиск | Новые сущности сразу индексируются |
| Документация | `/docs` обновляется вместе с кодом; расхождение считается дефектом |
| Демо-данные | `itms seed --demo` расширяется на сущности новой фазы |
| Бэкап/восстановление | Процедура проверяется после каждой фазы, добавляющей хранилище |

## Критерии готовности продукта (после Phase 7)

1. `docker compose up -d` разворачивает систему; первая учётная запись создаётся установочной командой.
2. Инфраструктура реальной серверной вносится и отображается во всех проекциях: список, карточка, схема, стойка, электрическая модель, план.
3. Карточка любого объекта показывает все связи и полную историю.
4. Проект модернизации проходит путь от снимка текущего состояния до обновления модели.
5. Расчёт мощности воспроизводим и объясним по шагам.
6. Все отчёты из §22 выгружаются в CSV/XLSX/PDF.
7. Поиск находит объект по IP, MAC, hostname, серийнику, номеру порта, тексту документа.
8. Аудит содержит «кто, что, когда, было → стало» по всем ключевым сущностям.

## Вопросы к согласованию перед Phase 1

| № | Вопрос | Варианты | Рекомендация |
|---|---|---|---|
| 1 | Размещение кода | Отдельное дерево `/itms` в этом репозитории · отдельный репозиторий | `/itms` в текущем репозитории: существующее приложение не затрагивается, при необходимости выделяется `git subtree split` |
| 2 | Судьба существующего приложения Personal Finance AI | Оставить как есть · вынести · удалить | Оставить как есть |
| 3 | Язык интерфейса | Русский · двуязычный | Русский, строки вынесены в словарь для последующей локализации |
| 4 | Единицы и стандарты электрики | 230/400 В, cos φ 0.95, derating 0.8, запас 20% | Принять как значения по умолчанию, настраиваемые в справочнике |
| 5 | Учётные записи исполнителей | Только владелец · владелец + ограниченный вход исполнителей | Только владелец в Phase 1–5; модель прав заложена и включается в Phase 6 |
| 6 | Глубина учёта времени | Только оценки · оценки + фактические трудозатраты | Оценки + факт (нужно для план/факт и отчёта «работы за период») |
| 7 | Хранение файлов | MinIO · файловая система тома | MinIO: единый механизм ссылок, дедупликация, подписанные URL |
| 8 | Импорт существующих данных | Есть ли выгрузки (Excel/NetBox/Zabbix) для первичного наполнения | От этого зависит приоритет CSV-импорта в Phase 2 |
