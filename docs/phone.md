# Телефон: iPhone и Apple Watch

День с людьми считается без телефона: Telegram и почта уже приходят в ядро,
и этого хватает, чтобы видеть, кто написал и кто ждёт ответа
(`docs/conversations.md`, блок «День с людьми»). Выгрузку с iPhone,
ярлыки и Health Auto Export настраивать не нужно — и брифинг их не ждёт.

Ниже — отдельный сервис `phone/`, если когда-нибудь появится источник,
который сам отдаёт данные. Сейчас он не часть обычной жизни ассистента.

Мост живёт в `phone/` — отдельный сервис со своим процессом, своей базой
и своим окружением. Ядро знает про него одну строку: адрес MCP-сервера.

Данные забираются из первоисточников Apple, а не собираются руками в
«Командах». Ярлык — запасной вход, не способ жить.

```
Здоровье (export.zip / Health Auto Export)
Messages на Mac (chat.db)          ──▶  phone.db  ──▶  /mcp ──MCP──▶ ядро
CallHistory на Mac / копия iPhone                                   Cursor
```

## Откуда что берётся

У Apple нет публичного «аккаунта здоровья», из которого сервер мог бы
скачать ваши шаги по логину. HealthKit живёт на устройстве. Зато устройство
умеет отдать **всё**, что знает, целиком — и именно этим мост пользуется.

| Что нужно | Откуда | Как часто | Участие человека |
| --- | --- | --- | --- |
| Все метрики Здоровья, кольца, тренировки, стадии сна | «Здоровье → Экспортировать медданные» (`export.zip`) | один раз, потом раз в несколько месяцев | выбрать «Экспортировать» |
| Те же метрики дальше, сами | приложение [Health Auto Export](https://www.healthexport.app/) | по расписанию, все метрики | один раз настроить автоматизацию в приложении |
| Звонки, FaceTime, WhatsApp/Telegram через систему | `CallHistory.storedata` на Mac (iCloud) | агент `mac-sync --watch` | включить синхронизацию iCloud |
| iMessage и SMS | `~/Library/Messages/chat.db` на Mac | тот же агент | «Сообщения в iCloud» |
| То же, если Mac нет | незашифрованная резервная копия iPhone в Finder | `import-backup` после новой копии | поставить iPhone на кабель |

Почему не «логин в аккаунт Apple»: такого API нет. Выгрузка из «Здоровья» —
официальный полный снимок; базы на Mac — то, что iCloud и так кладёт на
диск; Health Auto Export читает HealthKit целиком и сам шлёт JSON, без
сборки ярлыка из пяти блоков.

Здоровье из резервной копии не читаем: Apple держит его в отдельном
зашифрованном хранилище. Для истории здоровья — только `export.zip`.

## Как забрать

Поставить устройство на учёт (с самой машины моста):

```bash
curl -s -X POST http://127.0.0.1:8820/v1/devices/register \
  -H 'Authorization: Bearer $PHONE_ENROLL_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"name": "iPhone", "kind": "iphone"}'
```

Дальше — команды, не конструктор ярлыков.

### 1. Вся история Здоровья

На iPhone: «Здоровье» → фото профиля → «Экспортировать медданные».
Получится `export.zip` на несколько сотен мегабайт или гигабайт — в нём
каждый замер за все годы, не «шаги и сон».

```bash
python -m phone import-health ~/Downloads/export.zip
```

Повторная заливка того же файла безвредна: уже виденное останется
на месте, новое доедет. Импорт пишет пачками — построчная запись на
миллионах замеров превращает вечер в ночь.

### 2. Чтобы дальше ехало само

В Health Auto Export:

1. автоматизация REST API, JSON, Version 2;
2. тип данных — Health Metrics, **все** метрики, Summarize Data выкл.;
3. вторая автоматизация — Workouts, Version 2, с метриками тренировки;
4. адрес `https://<ваш-домен>/phone/v1/sync`, заголовок
   `X-Device-Token: <токен>`, Batch Requests вкл.

Приложение само ходит в HealthKit и само шлёт. Ярлык для этого не нужен.
Мост понимает формат приложения как свой: составные точки (ночь = сон +
глубокий + REM, пульс = среднее/мин/макс) разворачиваются в отдельные
замеры.

### 3. Звонки и переписка с Mac

iCloud кладёт на Mac ту же переписку и тот же журнал звонков, что на
iPhone. Агент читает базы напрямую.

```bash
python -m phone mac-sync                 # один проход
python -m phone mac-sync --watch         # следить и забирать новое
```

Если мост на сервере, а базы — на маке:

```bash
python -m phone mac-sync --watch \
  --url https://<ваш-домен>/phone \
  --token <токен устройства>
```

Текст сообщений на сервер не уезжает: только кто, когда, в какую сторону
и сколько знаков. Для «кто ждёт ответа» содержания не нужно.

### 4. Нет Mac — копия iPhone

Finder → iPhone → «Создать резервную копию», **без пароля**.

```bash
python -m phone import-backup            # последняя копия
python -m phone import-backup /путь/к/UDID
```

Зашифрованную копию мост не открывает: без пароля это мусор, а с паролем
это уже другая программа. В таком случае — «Сообщения в iCloud» на любом
Mac или выгрузка Здоровья.

## Что попадает в сводку

Не короткий список «шаги и сон», а всё, что реально пришло: пульс и HRV,
стадии сна, кольца Watch, VO2max, давление, вес, вода, еда, походка,
тренировки. Каждое число стоит рядом с собственной нормой человека
(медиана за `PHONE_BASELINE_DAYS` дней). Один марафон норму не задирает,
сегодняшний день в неё не входит.

Если один и тот же шаг записали часы и телефон, в день попадает один
источник — тот, что ближе к телу. Иначе выгрузка за пять лет молча
удвоила бы каждый день.

Ночь принадлежит утру: сон с 23:00 до 07:00 — это сегодня.

Пропущенный звонок и сообщение без ответа — одно незакрытое дело на
человека. Свежее входящее не долг первые `PHONE_REPLY_GRACE_MINUTES`
минут.

## HTTP и MCP

`/v1/*` — приём пакетов от Health Auto Export и агента на Mac. Полная
выгрузка Здоровья и базы Apple забираются командами выше: файл на
гигабайт тащить POST-ом незачем.

| Запрос | Зачем |
| --- | --- |
| `POST /v1/devices/register` | поставить устройство на учёт |
| `POST /v1/sync` | пакет от Health Auto Export или `mac-sync --url` |
| `POST /v1/calls`, `/v1/messages`, `/v1/samples`, `/v1/workouts`, `/v1/state` | узкий вход, если пакет уже разобран |
| `GET /v1/outbox`, `POST /v1/outbox/ack` | очередь заданий обратно на устройство |
| `GET /v1/summary` | та же сводка, что видит модель |
| `GET /health` | жив ли мост и когда что-то в него попадало |

Наружу — `POST /mcp`, Streamable HTTP. Реализованы обе эпохи протокола:

* **2026-07-28** — без сессий. Версия в `_meta`, метод и имя — в
  заголовках `Mcp-Method` и `Mcp-Name`. Иначе шлюз не маршрутизирует,
  не читая тело.
* **2025-11-25 / 2025-06-18** — рукопожатие `initialize`.

### Инструменты

| Инструмент | Что отвечает |
| --- | --- |
| `phone_today` | сводка дня: все пришедшие метрики против нормы, звонки, переписка |
| `phone_attention` | что требует внимания прямо сейчас |
| `phone_health` | одна метрика по дням: значения, среднее, норма, тренд |
| `phone_sleep` | сон за последние ночи вместе с пульсом покоя и HRV |
| `phone_calls` | журнал звонков, можно только пропущенные |
| `phone_messages` | кто и сколько писал (без текста) |
| `phone_workouts` | тренировки с часов |
| `phone_devices` | состояние моста: синхронизация, источники, заряд |
| `phone_push` | положить задание устройству: уведомление или напоминание |

Ресурсы: `phone://today`, `phone://attention`, `phone://devices`,
`phone://metrics`.

## Приватность

Текст переписки не хранится и с Mac не уезжает. От сообщения остаются
форма и метаданные. Включается осознанно: `PHONE_STORE_TEXT=1`.

Сервис слушает `127.0.0.1`. Наружу nginx выставляет только `/v1`. Токен
устройства показывается один раз, в базе лежит хеш. Чужой `Origin` на
`/mcp` получает `403`.

`PHONE_RETENTION_DAYS=0` — хранить всё. Иначе фоновая уборка съест
выгрузку Здоровья за годы.

## Подключение к ядру

В `/etc/assistant.env`:

```
MCP_SERVERS=phone=http://127.0.0.1:8820/mcp
MCP_PHONE_TOKEN=<PHONE_MCP_TOKEN моста>
```

Что появляется у ядра:

* `mcp.phone` в `/api/integrations`;
* блок «Телефон и здоровье» в промпте;
* строка «Самочувствие» в утреннем брифинге;
* `phone` в `/api/overview`;
* `GET /api/mcp`, `POST /api/mcp/read`, `POST /api/mcp/call`.

Чтение идёт напрямую. `phone_push` — действие `mcp.tool.call`, риск
MEDIUM, с подтверждением.

## Подключение к Cursor

```json
{"mcpServers": {"jarvis-phone": {
  "command": "/opt/assistant/venv/bin/python",
  "args": ["-m", "phone", "--stdio"],
  "env": {"PHONE_DB": "/opt/assistant/phone.db"}}}}
```

## Деплой

```ini
# /etc/systemd/system/assistant-phone.service
[Unit]
Description=JARVIS phone bridge
After=network-online.target

[Service]
Type=simple
User=assistant
WorkingDirectory=/opt/assistant
EnvironmentFile=/etc/assistant-phone.env
ExecStart=/opt/assistant/venv/bin/python -m phone
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Агент на Mac, если мост на сервере:

```ini
# ~/Library/LaunchAgents/jarvis-phone-sync.plist — mac-sync --watch --url … --token …
```

nginx выставляет приём (для Health Auto Export и удалённого агента):

```nginx
location /phone/v1/ {
    proxy_pass http://127.0.0.1:8820/v1/;
    client_max_body_size 32m;
}
```

Полная выгрузка Здоровья на сервер не качается через nginx — её заливает
`import-health` рядом с базой.

```bash
curl -s http://127.0.0.1:8820/health
python -m pytest phone/tests -q
```

`/health` отвечает `degraded`, если в мост ничего не попадало дольше
`PHONE_SILENCE_HOURS`: молчащий мост выглядит как «всё хорошо, данных
просто нет», и это худший вид поломки.
