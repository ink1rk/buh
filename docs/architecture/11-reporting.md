# 11 — Reporting (отчёты и аналитика)

## 1. Подход

Отчёт — это **зарегистрированный датасет + определение представления**, а не отдельная страница с SQL внутри. Такой подход даёт конструктор отчётов без риска произвольного SQL от пользователя.

```
dataset (в коде)            report_definition (в БД)         report_run
─────────────────           ────────────────────────         ──────────
имя, описание,              выбранные поля,                  параметры запуска,
доступные поля,             фильтры, группировка,            формат, файл,
доступные фильтры,          сортировка, диаграмма            число строк,
безопасный построитель                                       статус
```

Пользователь в интерфейсе выбирает датасет, поля, фильтры и группировку; система строит SQL только из разрешённых элементов (whitelist). Это исключает SQL-инъекции и неконтролируемые тяжёлые запросы.

## 2. Каталог датасетов

| Датасет | Основа | Ключевые поля | Типичные фильтры |
|---|---|---|---|
| `tasks` | `task` + project + employee + CI | тип, статус, приоритет, исполнитель, проект, сроки, оценка, факт | период, исполнитель, тип, просрочка |
| `overdue_tasks` | `tasks` с предикатом | дни просрочки | исполнитель, проект, критичность объекта |
| `employees` | `employee` + агрегаты | задачи открытые/просроченные/закрытые, время | отдел, линия, активность |
| `workload` | `task` + `time_entry` | план по дням, факт, ёмкость, утилизация | неделя, сотрудник |
| `projects` | `project` + агрегаты | статус, прогресс, здоровье, план/факт по срокам и бюджету | статус, владелец, период |
| `project_status` | срез по статусам | количество, суммы бюджета | — |
| `infrastructure` | `ci` + location + owner | тип, статус, критичность, размещение, владелец, возраст | тип, площадка, статус |
| `equipment` | `device` + модель | производитель, модель, S/N, гарантия, возраст | производитель, срок гарантии |
| `rack_capacity` | `rack` + `rack_mount` | занято U, свободно U, крупнейший свободный блок, вес, мощность | площадка, помещение |
| `free_resources` | порты, U, адреса, розетки | свободно/занято/всего | тип ресурса, площадка |
| `power` | `power_node_computed` | подключённая, расчётная, измеренная нагрузка, % загрузки, резерв, фазы | узел, стойка, помещение |
| `changes` | `change` | тип, риск, статус, окно, результат, объекты | период, статус, исполнитель |
| `incidents` | `incident` | сервис, severity, время реакции/решения, простой, SLA | период, сервис, нарушение SLA |
| `documents` | `document` | тип, статус, владелец, дата пересмотра, связи | тип, статус, просрочка пересмотра |
| `documents_review_due` | срез | дней до/после срока | горизонт |
| `domains_certs` | `domain`, `certificate` | срок действия, владелец, регистратор, связанные сервисы | горизонт истечения |
| `orphans` | `ci` без владельца / документации / размещения | тип нарушения | тип объекта |
| `work_log` | `time_entry` + `task` | дата, сотрудник, задача, объект, минуты | период, сотрудник, проект |
| `audit` | `audit_log` + `audit_change` | кто, что, когда, было → стало | период, сущность, актор |

Каждый датасет описан в коде как объект с перечнем колонок, типов, допустимых операторов фильтрации и правил соединения таблиц. Новый отчёт для существующего датасета не требует программирования.

## 3. Конструктор

Возможности интерфейса:

- выбор датасета и колонок (с описаниями);
- фильтры с типизированными операторами (`=`, `≠`, `>`, `<`, `между`, `в списке`, `содержит`, `пусто`, `за период`);
- комбинирование условий группами И/ИЛИ (дерево, ограниченная глубина);
- группировка до 2 уровней с агрегатами: количество, сумма, среднее, минимум, максимум, процент;
- сортировка по нескольким колонкам;
- итоги и подытоги;
- диаграмма: столбцы, линии, круговая, стековые столбцы;
- сохранение как `report_definition`, закрепление на дашборде;
- параметры запуска (например, период) запрашиваются при каждом запуске.

Предустановленные системные отчёты закрывают список из §22 постановки и служат примерами для собственных.

## 4. Аналитические представления

Помимо табличных отчётов — несколько специализированных экранов, где визуализация важнее таблицы:

| Экран | Что показывает |
|---|---|
| Загрузка отдела | Недельная тепловая сетка сотрудник × день, перегруз, клик → задачи дня |
| Портфель проектов | Проекты по статусам, прогресс, здоровье, вехи на общей шкале |
| Ёмкость ЦОД | Стойки: занятые U, вес, мощность; свободные непрерывные блоки |
| Энергетика | Дерево питания с загрузкой узлов, дисбаланс фаз, резервы, прогноз по сценариям |
| Надёжность | Инциденты по сервисам, время восстановления, соблюдение SLA, повторяющиеся проблемы |
| Качество CMDB | Полнота модели: доли объектов с владельцем, документацией, размещением, питанием |
| Сроки | Единая лента истечений: сертификаты, домены, гарантии, лицензии, пересмотр документов |

## 5. Экспорт

| Формат | Реализация | Особенности |
|---|---|---|
| **CSV** | Потоковая генерация на сервере | Для больших выгрузок; UTF-8 с BOM для Excel |
| **XLSX** | `openpyxl` в воркере | Форматирование, автофильтр, закреплённая шапка, листы по группам |
| **PDF** | HTML-шаблон → WeasyPrint | Титул, колонтитулы, дата, автор, номера страниц, встроенные схемы |
| **JSON** | Сериализация датасета | Для интеграций и резервных копий |

Правила:
- отчёты до 5 000 строк формируются синхронно, больше — фоновой задачей (`job`) с уведомлением о готовности;
- результат сохраняется в MinIO (`file_object`) и доступен по подписанной ссылке ограниченное время;
- запуски логируются в `report_run` — видно, кто и что выгружал (это часть аудита).

Пакет документов для согласования (например, с управляющей компанией) — это составной PDF: расчёт мощности + однолинейная схема + план стоек + спецификация. Формируется как отчёт с несколькими разделами и сразу прикладывается к проекту как документ.

## 6. Производительность

| Механизм | Назначение |
|---|---|
| Keyset-пагинация при просмотре | Стабильная скорость на больших выборках |
| Ограничение на число строк в интерактивном режиме (по умолчанию 1 000) | Защита интерфейса |
| Выполнение тяжёлых отчётов в воркере | Не блокирует API |
| `statement_timeout` для отчётных запросов | Защита БД |
| Кэш агрегатов (`*_computed`) | Мгновенные дашборды |
| Предрасчёт витрин по расписанию (загрузка, ёмкость, энергетика) | Стабильное время отклика |

## 7. Расписания и рассылки

`report_definition` может иметь расписание: ежедневно/еженедельно/ежемесячно. Воркер формирует файл и создаёт уведомление со ссылкой. Внешняя рассылка (email/Telegram) не реализуется на этом этапе, но является подписчиком того же события.

Типовые регулярные отчёты: еженедельная сводка по задачам и просрочкам, ежемесячный отчёт по изменениям и инцидентам, ежеквартальный отчёт по ёмкости и энергетике.
