# Web UI

`assistant/web/`. Панель управления ассистентом: что происходит, что он знает
и что собирается сделать.

Интерфейс не имеет собственного бэкенда и собственной базы. Он целиком стоит
на Core API — том же, которым пользуются Telegram-бот и `tg-user`. Поэтому
всё, что видно на экране, видно и боту, а любое расхождение между ними было
бы расхождением с самим ядром.

## Почему без сборки

Статика отдаётся самим FastAPI с `/ui`, разметка и логика — обычные HTML, CSS
и JS-модуль. Ни npm, ни бандлера, ни второго контейнера: ассистент ставится
копированием файлов и перезапуском сервиса, и интерфейс ставится так же.

В репозитории есть `frontend/` на React — это интерфейс финансового
приложения, отдельного продукта со своим бэкендом и своим Docker-образом.
JARVIS обращается к нему как к интеграции; смешивать их сборки незачем.

## Экраны

| Экран | Что показывает | Откуда данные |
|---|---|---|
| Сегодня | приветствие, счётчики внимания, новые сообщения, обязательства, состояние систем | `GET /api/overview` |
| Чат | переписка с ассистентом через общий конвейер | `POST /api/chat` |
| Входящие | подсказки ответов, что обещал владелец, кого он ждёт | `/api/suggestions`, `/api/commitments` |
| Память | записи с источником и датой, поиск, фильтр по типу, правка и удаление | `/api/memory` |
| Люди | список контактов и карточка: стиль, память, обязательства, диалоги | `/api/contacts`, `/api/contacts/{id}/context` |
| Диалоги | переписка, резюме, эпизоды, открытые обязательства | `/api/conversations` |
| Новости | сюжеты, сведённые по источникам | `GET /news` |
| Активность | журнал событий, переход по цепочке `correlation_id` | `/api/activity` |
| Действия | очередь действий, подтверждение и отмена | `/api/actions` |
| Интеграции | состояние внешних систем на момент открытия | `/api/integrations?refresh=true` |
| Уведомления | история и то, что отложено в дайджест | `/api/notifications` |
| Настройки | режим ответов, права на действия, доступ к панели | `/api/permissions`, `/api/health` |

Экранов «Финансы», «Рынки», «Календарь» и «Задачи» пока нет: за ними нет
готовой функциональности, а рисовать пустые разделы — врать про готовность.

## Что видно про память

У каждой записи показан источник словами, а не кодом: «сказано напрямую», «из
переписки в Telegram», «вывод модели, не факт». Последний помечен жёлтым,
потому что догадка модели и слова владельца — это разные вещи, и владелец
должен видеть разницу, не открывая базу.

Удаление настоящее и каскадное: строка исчезает из БД вместе со всем, что от
неё зависело. Подробности — в [conversations.md](conversations.md).

## Доступ

Ядро слушает на всех интерфейсах, а внутри лежит личная переписка. Доступ
закрывается переменной окружения:

```
ASSISTANT_WEB_TOKEN=<длинная случайная строка>
```

Когда токен задан, запросы к данным требуют его в заголовке
`X-Assistant-Token`, в cookie `assistant_token` или в параметре `?token=`.
Панель спрашивает токен один раз и хранит его в `localStorage`.

Запросы с самой машины (`127.0.0.1`, `::1`) проходят без токена. Иначе бота и
`tg-user` пришлось бы учить хранить секрет ради защиты от угрозы, которой на
петле нет.

Статика `/ui` отдаётся без токена: в ней нет данных, она сама спрашивает
токен и проверяет его обычным запросом к API.

Пока `ASSISTANT_WEB_TOKEN` не задан, поведение прежнее — доступ открыт всем в
сети. Молча менять это на работающей системе нельзя, поэтому вместо запрета
`GET /api/health` возвращает предупреждение, а панель показывает его на
главной и в настройках.

## Сводка главного экрана

`GET /api/overview` собирает главный экран одним запросом: приветствие по
времени суток, счётчики внимания, первые подсказки и обязательства с именами
контактов, состояние интеграций. Иначе главная тянула бы пять запросов и
показывала бы их вразнобой.
