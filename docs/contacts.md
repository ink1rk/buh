# Контакты

`domain/contacts.py`. Контакт — это человек, а не чат: один и тот же человек
может приходить как Telegram-идентификатор, адрес почты и три прозвища.

## Модель

| Поле | Назначение |
|---|---|
| `id`, `display_name`, `first_name`, `last_name` | идентичность |
| `aliases` | прозвища и username-ы |
| `telegram_ids`, `emails`, `phones` | идентификаторы в каналах |
| `notes` | заметки владельца |
| `importance` | 0…1, влияет на срочность уведомлений |
| `relationship_type` | `FAMILY`, `FRIEND`, `COLLEAGUE`, `MANAGER`, `CLIENT`, `CONTRACTOR`, `SERVICE`, `UNKNOWN` |
| `relationship_source` | `USER_EXPLICIT` или `LLM_INFERENCE` |
| `communication_style` | наблюдаемая манера переписки |
| `is_owner` | владелец системы |
| `last_interaction_at` | последний контакт |

Тип отношений автоматически не «угадывается как факт»: пока владелец не указал
его сам, значение остаётся `UNKNOWN`, а источник — `LLM_INFERENCE`, и карточка
честно пишет «(предположение)».

## Entity resolution

`resolve_one(query)` возвращает пару `(контакт, кандидаты)`.

Порядок сопоставления:

1. числовой запрос → Telegram-идентификатор (точное совпадение, вес 1.0);
2. запрос с `@` → адрес почты (1.0);
3. полное совпадение имени или алиаса (1.0);
4. вхождение подстроки (0.8);
5. совпадение по корню имени (0.7) — таблица `NAME_STEMS` знает, что «Серёга»,
   «Серый» и «Сергун» — это «Сергей»;
6. бонус 0.15, если контакт упоминался в текущем контексте, и до 0.05 за
   важность.

Если лучших кандидатов больше одного (разница веса менее 0.05), контакт **не**
выбирается: ассистент спрашивает.

```
«Напиши Серёге»

Нашла несколько подходящих:
• Сергей Иванов — colleague
• Сергей Петров — friend

Кого имеешь в виду?
```

## Стиль общения

Определяется по наблюдаемым признакам переписки, без психологических выводов:

| Признак | Как считается |
|---|---|
| `length` | средняя длина сообщений: short < 80, medium < 250, long |
| `formality` | доля сообщений с «вы», «здравствуйте», «добрый день» |
| `emoji` | доля сообщений с эмодзи: often / sometimes / rare |
| `samples` | три последние реплики как образец манеры |

Стиль используется только для генерации черновиков ответа. Для диалога
владельца с самим ассистентом стиль не считается.

## Профиль

`GET /api/contacts/{id}/context` собирает карточку из структурированных данных,
а не из LLM-блоба:

* сам контакт;
* открытые обязательства в обе стороны;
* релевантная память о человеке;
* последние эпизоды;
* диалоги и их summary.

В Telegram та же карточка — команда `/who Сергей`.

## API

```
GET    /api/contacts
GET    /api/contacts/resolve?q=Серёга     разрешение имени + кандидаты
GET    /api/contacts/{id}
GET    /api/contacts/{id}/context         полный профиль
PATCH  /api/contacts/{id}                 имя, заметки, отношения, важность, алиасы
DELETE /api/contacts/{id}
```

Изменение `relationship_type` через API переводит `relationship_source` в
`USER_EXPLICIT`: указание владельца перестаёт быть догадкой.
