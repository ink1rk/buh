# MCP-сервер

Приложение умеет отдавать ваши финансы AI-ассистентам по протоколу
[Model Context Protocol](https://modelcontextprotocol.io). Claude Desktop, Cursor
или любой другой MCP-клиент получает доступ к реальным счетам, операциям, целям и
капиталу — и отвечает на вопросы по вашим данным, а не по догадкам.

## Сразу о главном: MCP не заменяет коннектор к банку

Это два разных уровня, и их легко спутать.

- **MCP — это протокол между AI-ассистентом и вашими инструментами.** Он не умеет
  логиниться в банк и не даёт доступа к данным, которых у вас нет. Ozon Банк не
  публикует API для физлиц, и MCP этого не меняет: выписку всё равно нужно
  выгрузить.
- **Коннектор — это то, откуда берутся данные.** Он и решает задачу «следить за
  финансами».

Так что MCP-сервер не ускоряет получение банковских данных. Он меняет другое: как
вы с этими данными работаете после импорта.

## Что даёт MCP на практике

Без MCP, чтобы понять «сколько ушло на еду вне дома за три месяца и что с этим
делать», нужно открыть приложение, зайти в аналитику, выбрать период, сложить
категории. С MCP это один вопрос ассистенту, который сам вызовет нужные
инструменты и сопоставит ответ с вашими целями.

Что становится возможным:

- **Вопросы на естественном языке по реальным цифрам.** «Я укладываюсь в бюджет?»,
  «на чём я стабильно переплачиваю?», «хватит ли подушки на полгода?»
- **Ввод операций из любого чата.** `add_transaction` принимает «-450 кофе».
- **Загрузка выписки без браузера.** `import_bank_statement` берёт файл по пути на
  диске: «загрузи вот эту выписку» — и операции уже в штабе.
- **Сквозные рассуждения.** Ассистент может за один заход посмотреть траты,
  прогноз, цели и капитал — то есть сделать то, для чего в интерфейсе нужно
  обойти пять экранов.
- **Работа в вашем редакторе или мессенджере,** без переключения контекста.

Чего MCP **не** даёт: новых источников данных, автоматической синхронизации с
банком, и он не отменяет необходимость выгружать выписку.

Стоит ли включать: да, если вы уже пользуетесь Claude Desktop или Cursor — выигрыш
ощутимый и настройка занимает одну правку конфига. Если нет, ценность нулевая:
веб-интерфейс покрывает всё то же самое.

## Настройка

Зависимостей помимо `httpx` нет — протокол реализован напрямую, поэтому ставить
SDK не нужно.

### Claude Desktop

`~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) или
`%APPDATA%\Claude\claude_desktop_config.json` (Windows):

```json
{
  "mcpServers": {
    "finance": {
      "command": "/opt/personal-finance-ai/backend/.venv/bin/python",
      "args": ["-m", "app.mcp.server"],
      "cwd": "/opt/personal-finance-ai/backend",
      "env": {
        "FINANCE_API_URL": "http://127.0.0.1:8000/api/v1",
        "PYTHONPATH": "."
      }
    }
  }
}
```

### Cursor

`.cursor/mcp.json` в проекте или `~/.cursor/mcp.json` — формат тот же.

### Если приложение на сервере

Укажите его адрес в `FINANCE_API_URL`, например
`http://192.168.1.50/api/v1`. Сервер ходит к приложению по HTTP, а не в файл базы,
поэтому его можно запускать на ноутбуке, пока приложение живёт на виртуалке.

У API нет аутентификации (приложение рассчитано на локальную сеть), так что
**не выставляйте его в интернет** без прокси с авторизацией. Если такой прокси
есть, передайте токен через `FINANCE_API_TOKEN` — он уйдёт заголовком
`Authorization: Bearer`.

### Проверка

```bash
cd backend
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
  | FINANCE_API_URL=http://127.0.0.1:8000/api/v1 PYTHONPATH=. .venv/bin/python -m app.mcp.server
```

В ответ придут результат рукопожатия и список инструментов. Логи идут в stderr:
stdout занят протоколом.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `get_financial_overview` | сводка: балансы, доходы и расходы месяца, Health Score, капитал, инсайты |
| `list_accounts` | счета с балансами |
| `search_transactions` | поиск операций с итогами и разбивкой по категориям |
| `add_transaction` | записать операцию текстом («-450 кофе») |
| `get_spending_analytics` | аналитика за период: категории, тренды, поток |
| `get_forecast` | прогноз по среднему полных месяцев выписки |
| `get_financial_review` | разбор выписки: средние, категории, места, советы |
| `get_net_worth` | чистый капитал: активы и обязательства |
| `list_goals` | цели с прогрессом и вероятностью |
| `get_budget` | месячный план расходов |
| `list_calendar` | платежи и счета финансового календаря |
| `analyze_purchase` | оценка покупки: доля капитала, часы работы, влияние на цели |
| `list_bank_connections` | подключённые банки и их статус |
| `import_bank_statement` | загрузить файл выписки по пути на диске |
| `sync_bank_connection` | синхронизация через Открытое API банка |
| `list_bank_imports` | история импортов |

`search_transactions` возвращает не только строки, но и агрегаты — сумму трат,
поступления и разбивку по категориям, отсортированную по убыванию. Это сделано
намеренно: на вопрос «сколько ушло на кофе» модель должна читать готовый ответ, а
не складывать пятьсот строк, ошибаясь в арифметике.

Три инструмента меняют данные: `add_transaction`, `import_bank_statement` и
`sync_bank_connection`. Каждый объявляет это в `tools/list` через
`annotations.readOnlyHint: false`, и клиент по этой пометке решает, нужно ли
спрашивать владельца. Пометка обязательна: ассистент считает пишущим всё, про
что сервер не сказал обратного, и такой инструмент к нему попадёт только через
движок действий — с разрешениями, подтверждением и журналом.

## Устройство

- `app/mcp/tools.py` — контракт и обработчики инструментов. Не зависит от MCP,
  поэтому тестируется напрямую.
- `app/mcp/client.py` — HTTP-клиент к финансовому API.
- `app/mcp/server.py` — транспорт: JSON-RPC 2.0 поверх stdio, методы
  `initialize`, `tools/list`, `tools/call`, `ping`.

Протокол реализован без официального SDK сознательно: единственная зависимость
остаётся `httpx`, который в бэкенде уже есть, а SDK переименовал серверный API
между версиями 1.x и 2.x. Поддерживаются версии протокола `2025-06-18`,
`2025-03-26` и `2024-11-05`.

Ошибки инструментов возвращаются как результат с `isError: true`, а не как ошибка
протокола — тогда ассистент видит причину и может исправиться сам, вместо того
чтобы потерять соединение.
