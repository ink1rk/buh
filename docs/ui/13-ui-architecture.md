# 13 — UI Architecture

## 1. Принципы интерфейса

Система — рабочий инструмент руководителя ИТ, а не витрина. Отсюда требования:

| Принцип | Как выражается |
|---|---|
| Desktop-first | Раскладка рассчитана на 1440–2560 px; планшет — упрощённо; телефон — только просмотр ключевых экранов |
| Плотность | Строка таблицы 32 px, базовый кегль 13 px, отступы 4/8/12/16 |
| Информация вместо украшений | Никаких крупных карточек-плиток, градиентов и иллюстраций; максимум данных на экран |
| Связи всегда рядом | На карточке любого объекта панель связанных сущностей — не «ещё одна вкладка внизу» |
| Скорость работы | Командная палитра, горячие клавиши, inline-редактирование, массовые операции |
| Предсказуемость | Одинаковые паттерны: список → карточка → контекстная панель; одинаковые фильтры везде |
| Тёмная и светлая темы | Обе полноценные, тёмная — по умолчанию |

Визуальный язык: нейтральные графитовые поверхности, один акцентный цвет, семантические цвета статусов (норма/внимание/авария/выключено), моноширинный шрифт для технических значений (IP, MAC, серийники, порты).

## 3. Структура фронтенда

```
itms/web/src/
  app/                 точка входа, роутер, провайдеры, темы
  shared/
    api/               сгенерированные типы OpenAPI + тонкий клиент
    ui/                дизайн-система: Button, Table, Dialog, Drawer, Badge,
                       Field, Combobox, DatePicker, Tabs, Toast, EmptyState
    hooks/             useHotkeys, useDebounce, useVirtualList, useUndoStack
    lib/               форматирование (байты, ватты, U, IP, даты), утилиты
  entities/            представление доменных сущностей (карточки, бейджи,
                       селекторы): ci, device, rack, service, task, document…
  features/            действия: перемещение в стойке, создание кабеля,
                       применение planned change, экспорт схемы, фильтры
  widgets/             составные блоки: RelatedPanel, HistoryTimeline,
                       DashboardBlocks, GanttChart, RackElevation
  pages/               экраны, собранные из виджетов
  editors/
    canvas-kernel/     общее ядро редакторов: viewport, выделение, snapping,
                       командный стек undo/redo, сериализация, экспорт SVG
    diagram/           сетевые/логические/силовые схемы (React Flow)
    rack/              редактор стоек (SVG + dnd-kit)
    floorplan/         планы помещений
    gantt/             диаграмма Ганта (SVG)
```

Слои импортируются сверху вниз (`pages → widgets → features → entities → shared`), обратные зависимости запрещены линтером. Это тот же принцип, что и на бэкенде: структура по смыслу, а не по типу файла.

**Canvas kernel** — ключевое решение: три редактора (схемы, стойки, планы) и Gantt разделяют общий механизм трансформации координат, выделения, привязки к сетке, отмены действий и экспорта в SVG. Это экономит реализацию и даёт одинаковое поведение горячих клавиш во всех редакторах.

## 4. Состояние

| Тип состояния | Инструмент | Примеры |
|---|---|---|
| Серверные данные | TanStack Query | Списки, карточки, отчёты; инвалидация по ключам сущностей |
| Состояние редактора | Zustand (по одному стору на открытый редактор) | Viewport, выделение, стек команд, несохранённые изменения |
| Состояние интерфейса | Zustand (глобально) | Тема, свёрнутая навигация, недавние объекты, настройки таблиц |
| Состояние URL | React Router | Фильтры списков, вкладки карточки, выбранный объект — всё в query-параметрах |

Правило: любое состояние, которым можно поделиться ссылкой (фильтры, открытый объект, режим схемы), живёт в URL. Это даёт «скопировать ссылку на отфильтрованный список» без дополнительной работы.

Оптимистичные обновления применяются для частых мелких действий: смена статуса задачи, перетаскивание в Kanban и в стойке, переименование. При ошибке — откат и тост с причиной.

## 5. Ключевые интерфейсные паттерны

### 5.1 Таблица объектов

Единый компонент для всех списков (TanStack Table + виртуализация):

- настраиваемый набор колонок, ширина, порядок; раскладка сохраняется в профиле;
- сортировка, группировка, плотный режим;
- фильтры в шапке + панель расширенных фильтров, сохранение как `saved_filter`;
- выделение строк и массовые операции;
- inline-редактирование ключевых полей (статус, владелец, срок);
- быстрый предпросмотр (`Space`) — карточка в боковой панели без ухода со списка;
- экспорт текущей выборки в CSV/XLSX.

### 5.2 Карточка объекта

Единый макет для CI любого типа:

```
Заголовок: имя, код, тип, статус, критичность, быстрые действия
Вкладки:   Обзор · Связи · Сеть · Питание · Размещение · Документы ·
           Задачи · Изменения · История
Правая панель: владелец, ответственный, размещение, теги, ключевые атрибуты
```

Вкладка «Связи» — граф и списки; вкладка «История» — лента аудита с указанием, в рамках какого изменения выполнена правка.

### 5.3 Контекстная панель связей

Присутствует на всех экранах: для выбранного объекта показывает свёрнутые блоки (размещение, питание, сеть, сервисы, документы, задачи). Каждый блок раскрывается и кликается. Это главный инструмент против «набора CRUD-страниц».

### 5.4 Командная палитра (Ctrl+K)

- поиск по всей системе (объекты, документы, задачи, проекты, IP, MAC, серийники);
- команды: создать объект, открыть схему, перейти в раздел, запустить отчёт, начать изменение;
- недавние объекты;
- контекстные действия для текущей страницы.

### 5.5 Редакторы

Общее поведение: панель инструментов слева, свойства выделенного справа, миникарта, масштаб, индикатор несохранённых изменений, `Ctrl+Z`/`Ctrl+Shift+Z`, `Ctrl+S`.

## 6. Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Ctrl+K` | Командная палитра |
| `/` | Фокус в поиск |
| `G` затем `D/I/N/R/P/T/C` | Переход: Дашборд / Инфраструктура / Сеть / Стойки / Проекты / Задачи / Изменения |
| `N` | Создать (контекстно: объект, задачу, изменение) |
| `E` | Редактировать текущий объект |
| `Space` | Быстрый предпросмотр выделенной строки |
| `J` / `K` | Следующая / предыдущая строка |
| `X` | Выделить строку (для массовых операций) |
| `F` | Панель фильтров |
| `Esc` | Закрыть панель/диалог |
| `?` | Список горячих клавиш |

В редакторах действует дополнительный набор (см. `06-diagram-engine.md`, `07-rack-and-power.md`).

## 7. Состояния интерфейса

Обязательны для каждого экрана:

| Состояние | Требование |
|---|---|
| Загрузка | Скелетоны, сохраняющие структуру (не спиннер по центру) |
| Пусто | Объяснение и действие («Нет стоек в этом помещении — добавить стойку») |
| Ошибка | Понятный текст + кнопка «Повторить» + `request_id` для журнала; стектрейсы не показываются |
| Нет прав | Явное сообщение, а не пустая страница |
| Частичная загрузка | Тяжёлые блоки (граф, расчёты) грузятся отдельно и не блокируют остальное |
| Несохранённые изменения | Предупреждение при уходе со страницы редактора |

## 8. Производительность

| Механизм | Где |
|---|---|
| Виртуализация строк | Все списки > 100 строк |
| Виртуализация рендера | Схемы, планы, Gantt |
| Code splitting по маршрутам и редакторам | React Flow и Gantt грузятся только при открытии |
| Дебаунс поиска и валидации размещения | 250–400 мс |
| Кэш и фоновая инвалидация TanStack Query | Мгновенные повторные открытия |
| Пагинация курсором | Крупные датасеты |
| Мемоизация тяжёлых узлов | Схемы, стойки |

Бюджет: первичная загрузка основного бандла < 300 КБ gzip (без редакторов), интерактивность списка на 10 000 строк без заметных задержек.

## 9. Доступность и мелочи, которые важны в работе

- Полная работа с клавиатуры: навигация по таблицам, диалогам, вкладкам.
- Видимый фокус, ARIA-атрибуты (Radix даёт это по умолчанию).
- Контраст не ниже AA в обеих темах.
- Копирование технических значений одним кликом (IP, MAC, серийник, код объекта).
- Единый формат дат и относительное время («2 дня назад») с абсолютным значением в подсказке.
- Тосты об успехе действий с кнопкой «Отменить» там, где откат возможен.
- Ссылки на объекты в текстах документов и комментариях — кликабельные.

---

## 10. Мобильная версия

Не приложение, а адаптация: дашборд, список задач, карточка задачи, карточка объекта (чтение), уведомления, поиск. Редакторы схем, стоек и планов на телефоне открываются в режиме просмотра с зумом. Это осознанное ограничение: инженерные редакторы не имеют смысла на маленьком экране.
